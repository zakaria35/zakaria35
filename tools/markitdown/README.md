# MarkItDown — بوّابة المنهاج إلى كيميا 📄→📝

**المشكلة:** المنهاج الفلسطيني للكيمياء موجود كملفات PDF وWord وعروض PowerPoint وصور أسئلة. النماذج اللغوية لا تقرأ هذه الصيغ مباشرة، وكيميا لا يستطيع الاستشهاد بما لا يقرأه.

**الحل:** [MarkItDown](https://github.com/microsoft/markitdown) — أداة من مايكروسوفت (رخصة MIT) تحوّل كل هذه الصيغ إلى **Markdown**، وهي الصيغة التي «تتكلّمها» النماذج اللغوية أصلاً، وتحفظ بنية المستند: العناوين والقوائم والجداول.

هذه الأداة تخدم مباشرةً **المرحلة 2 (الباحث الموثوق)**: قاعدة معرفة مبنية على الكتاب الوزاري نفسه، لا على تخمين النموذج.

---

## التثبيت

```bash
pip install -r tools/markitdown/requirements.txt
```

يُفضّل بيئة افتراضية (يتطلّب Python 3.10 أو أحدث):

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r tools/markitdown/requirements.txt
```

## الاستخدام

1. ضع مصادر المنهاج في `knowledge/raw/` — ونظّمها بمجلّدات إن أردت:

```
knowledge/raw/
├── الكتاب-الوزاري/
│   ├── الوحدة-1-الاتزان.pdf
│   └── الوحدة-2-الأحماض-والقواعد.pdf
├── امتحانات-سابقة/
│   └── وزاري-2024.pdf
└── أوراق-عمل/
    └── تمارين-التأكسد-والاختزال.docx
```

2. شغّل التحويل:

```bash
python3 tools/markitdown/ingest.py
```

3. النتيجة في `knowledge/md/` بنفس بنية المجلّدات، مع `INDEX.md` يفهرس كل ما تحوّل.

### خيارات

| الخيار | الوظيفة |
| --- | --- |
| `--source <مسار>` | مجلّد المصادر (افتراضياً `knowledge/raw`) |
| `--out <مسار>` | مجلّد المخرجات (افتراضياً `knowledge/md`) |
| `--force` | أعد التحويل حتى لو كان المخرج محدّثاً |

التشغيل **تراكمي**: الملفات التي لم يتغيّر مصدرها تُتجاوَز، فتضيف وحدةً جديدة دون إعادة معالجة الكتاب كلّه.

### الصيغ المدعومة

PDF · Word · PowerPoint · Excel · CSV · HTML · EPUB · صور · نصوص · JSON/XML · ZIP.

## الترويسة: من أين جاءت المعلومة

كل ملف مخرَج يبدأ بترويسة تحفظ أصله:

```markdown
---
source_file: "الكتاب-الوزاري/الوحدة-1-الاتزان.pdf"
source_format: "pdf"
converted_on: 2026-07-31
converted_by: "markitdown"
---
```

هذه ليست زينة: مبدأ المشروع أن **كل معلومة علمية بمصدر**. الترويسة تسمح لكيميا أن يقول للطالب «هذا من الوحدة الأولى من الكتاب الوزاري» بدل أن يجزم بلا سند.

## حدود يجب معرفتها

- **PDF الممسوح ضوئياً** (صورة لا نصّ) يخرج فارغاً — السكربت يعلّمه بـ `⚠` بدل أن يبتلع الخطأ بصمت. يحتاج OCR، وهذا مسار لاحق (`markitdown-ocr` أو Azure Document Intelligence).
- **المعادلات الكيميائية والرموز السفلية/العلوية** قد تفقد تنسيقها في التحويل. راجع مخرجات الوحدات الحسّاسة يدوياً قبل اعتمادها.
- **الجداول المعقّدة** في PDF قد تخرج مشوّشة الترتيب.
- **الترتيب في النصوص العربية** قد يختلّ في بعض ملفات PDF بحسب طريقة إنتاجها.

القاعدة: `knowledge/md/` مادّة **يُراجعها إنسان** قبل أن تصبح مرجعاً يستشهد به كيميا.

## الخطوة التالية

بعد تجهيز `knowledge/md/`، تُوصَل هذه المادّة بعقدة الوكيل في n8n كأداة بحث (Vector Store أو بحث نصّي) ضمن المرحلة 2 — فيصير كيميا يجيب من الكتاب الوزاري نفسه.

## المصدر

[microsoft/markitdown](https://github.com/microsoft/markitdown) — رخصة MIT. نستهلكه كحزمة من PyPI ولا ننسخ شيفرته داخل المستودع، ليبقى التحديث بتغيير رقم النسخة في `requirements.txt`.

> ملاحظة أمنية من مطوّري الأداة: MarkItDown يقرأ الملفات بصلاحيات المستخدم الذي يشغّله. حوّل ملفات تثق بمصدرها.
